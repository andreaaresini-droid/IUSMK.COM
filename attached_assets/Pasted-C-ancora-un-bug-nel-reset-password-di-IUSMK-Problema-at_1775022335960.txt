C’è ancora un bug nel reset password di IUSMK.

Problema attuale:
appena apro il link arrivato via email, la pagina reset-password mostra subito:
“Il link non è valido. Richiedi un nuovo link di recupero.”
succede immediatamente, senza che l’utente abbia ancora inviato una nuova password.

Quindi il token viene rifiutato o consumato troppo presto, già all’apertura della pagina.

Correggi SOLO questa parte, senza toccare Stripe, corsi, coupon, notifiche, admin o altre funzioni.

OBIETTIVO
Quando l’utente apre il link email:
- la pagina deve aprirsi normalmente
- il form per impostare la nuova password deve comparire
- il token NON deve essere segnato come usato
- il token deve essere invalidato SOLO dopo reset password completato con successo

CONTROLLI DA FARE

1. verifica come viene letto il token dall’URL nella pagina /reset-password
2. verifica che il token non venga troncato, decodificato male o alterato
3. verifica che eventuali parametri query vengano letti correttamente lato frontend
4. verifica che la chiamata iniziale di validazione token NON consumi il token
5. se esiste una GET /validate-reset-token o simile, deve solo controllare validità, non segnare usedAt e non invalidare nulla
6. se oggi il token viene invalidato o rifiutato appena si apre la pagina, rimuovi questa logica
7. il token deve essere marcato come usato SOLO nella POST finale che salva davvero la nuova password
8. controlla che Gmail/iPhone preview del link non faccia fallire il flusso
9. se la pagina oggi mostra errore immediato al mount, correggi il controllo iniziale
10. aggiungi log chiari:
   - [RESET_PAGE] token letto dall’URL
   - [RESET_PAGE] token presente / mancante
   - [RESET_PAGE] validazione iniziale ok / fail
   - [RESET_PASSWORD] token usato solo dopo update riuscito

COMPORTAMENTO CORRETTO
- utente apre link email
- la pagina mostra il form nuova password
- nessun errore immediato
- utente inserisce nuova password
- clicca salva
- backend aggiorna password
- solo allora il token viene invalidato

IMPORTANTE
Non fare patch parziali.
Rendi il reset password stabile su mobile, specialmente da Gmail/iPhone.
