Il reset password di IUSMK continua a non funzionare.

Situazione attuale:
- l’email di reset arriva correttamente
- la pagina reset-password si apre
- il form compare
- ma il token viene comunque considerato “non valido” già nella pagina, oppure prima del reset reale

Quindi il bug è ancora nella gestione del token.

Correggi SOLO questa parte, senza toccare Stripe, corsi, coupon, notifiche, admin o altre funzioni.

OBIETTIVO
Il token di reset deve funzionare così:
1. arriva via email
2. l’utente apre il link
3. la pagina mostra il form
4. il token resta valido
5. il backend aggiorna la password solo al submit
6. solo dopo successo reale il token viene invalidato

CONTROLLI OBBLIGATORI

1. Controlla come il token viene generato e salvato nel database.
2. Controlla come il token viene letto dalla query string della pagina reset-password.
3. Controlla se il token viene:
   - alterato
   - troncato
   - codificato/decodificato male
   - hashato in modo incoerente tra creazione e verifica
4. Controlla se il frontend fa una validazione iniziale troppo aggressiva che mostra “Link non valido” anche quando il token è corretto.
5. Se esiste una validazione iniziale del token:
   - deve solo verificare esistenza/scadenza
   - NON deve marcarlo come usato
   - NON deve mostrare errore se il token è ancora valido
6. Controlla che il backend usi lo stesso metodo di confronto token in creazione e in verifica finale.
7. Se il token nel DB è hashato, verifica che il confronto venga fatto correttamente.
8. Aggiungi log chiarissimi:
   - [RESET_TOKEN_CREATE] token generato
   - [RESET_TOKEN_CREATE] token hash salvato
   - [RESET_PAGE] token letto da URL
   - [RESET_PAGE] token valido sì/no
   - [RESET_SUBMIT] token ricevuto
   - [RESET_SUBMIT] token match sì/no
   - [RESET_SUBMIT] password aggiornata sì/no
   - [RESET_SUBMIT] token invalidato dopo successo
9. NON invalidare il token al load della pagina.
10. Invalida il token SOLO dopo update password riuscito.
11. Se oggi il frontend mostra “Link non valido” appena la validazione iniziale fallisce per un problema di parsing/query, correggi il parsing del token.
12. Verifica esplicitamente il comportamento su mobile Safari/Gmail iPhone.

COMPORTAMENTO CORRETTO FINALE
- apro il link email
- vedo il form senza errore
- inserisco nuova password
- clicco salva
- password aggiornata
- conferma di successo
- il token risulta usato solo dopo

IMPORTANTE
Non fare una patch superficiale.
Controlla davvero tutta la catena:
generazione token → salvataggio DB → lettura URL → verifica frontend → submit backend → invalidazione finale.
