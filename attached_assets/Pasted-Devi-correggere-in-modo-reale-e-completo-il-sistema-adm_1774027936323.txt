PRIORITÀ 1 — DASHBOARD ADMIN MOBILE DAVVERO USABILE
==================================================

PROBLEMA ATTUALE

- non riesco a navigare bene tra le sezioni
- non riesco a gestire bene il sito da smartphone
Il sito/admin sarà usato soprattutto da telefono, quindi la UX mobile è prioritaria.

OBIETTIVO
Rendere il pannello admin perfetto da smartphone.

MODIFICHE RICHIESTE

1. MENU MOBILE ADMIN
- Mantieni in alto logo IUSMK
- Aggiungi un menu hamburger funzionante
- Quando apro il menu devono comparire chiaramente:
  - Dashboard
  - Corsi
  - Codici di Accesso
  - Galleria
  - Richieste di Contatto
  - Credenziali Admin
  - Torna al sito
  - Esci
- Il menu deve essere realmente cliccabile su telefono
- Deve aprirsi e chiudersi bene

2. CARD/BLOCCHI DASHBOARD
- Le card statistiche nella dashboard admin mobile devono essere cliccabili
- Ogni card deve portare alla sezione giusta:
  - Studenti Totali → gestione studenti / overview studenti (se esiste, altrimenti pagina codici o dashboard dettagliata)
  - Codici Attivi → pagina “Codici di Accesso”
  - Corsi Pubblicati → pagina “Corsi”
  - Elementi Galleria → pagina “Galleria”
  - Richieste in Attesa → pagina “Richieste di Contatto”
- Se una sezione specifica non esiste, collega la card alla pagina più coerente
- Aggiungi hover/tap feedback mobile chiaro

3. DASHBOARD MOBILE LAYOUT
- Ottimizza spaziature e header mobile
- Evita testo tagliato
- Evita elementi che finiscono sotto la navbar o dietro overlay
- I pulsanti e link devono essere grandi abbastanza da cliccare bene col dito
- Nessun blocco deve essere “finto”: tutto ciò che sembra cliccabile deve esserlo davvero

PRIORITÀ 2 — CODICI DI ACCESSO: RIFARE LA LOGICA IN MODO FUNZIONANTE

- il sistema di sblocco è incoerente o rotto

Devi correggere completamente il flusso.

==================================================
A. CODICI PIÙ CORTI
==================================================

Voglio che i codici non siano più lunghi alfanumerici complicati.

NUOVA REGOLA:
- i codici devono essere brevi
- massimo 6 caratteri
- solo numeri oppure numeri + lettere maiuscole semplici, ma preferenza: solo numeri
- meglio se 6 cifre numeriche tipo:
  482193
  105874

IMPLEMENTAZIONE:
- genera codici casuali unici di 6 cifre
- assicurati che non ci siano duplicati nel database
- se un codice esiste già, rigeneralo
- aggiorna sia creazione codice che validazione codice

==================================================
B. MODIFICA CODICE GIÀ ESISTENTE
==================================================

Aggiungi nella dashboard admin, nella sezione “Codici di Accesso”, la possibilità di modificare un codice esistente.

Ogni codice deve poter essere modificato almeno nei seguenti campi:
- nome cliente
- email cliente
- corso associato
- stato (attivo/revocato/disattivato)
- scadenza (se prevista)
- note interne opzionali (se esiste questo campo, altrimenti aggiungilo)

IMPORTANTE:
- il codice stesso può restare invariato di default
- opzionalmente puoi aggiungere anche “Rigenera codice”
- la modifica deve salvare davvero nel database
- dopo il salvataggio, il sistema studente deve leggere i dati aggiornati

Nella tabella/lista admin aggiungi:
- tasto modifica per ogni codice
- modal o pagina modifica funzionante
- salvataggio reale
- feedback di conferma successo

==================================================
C. STESSA EMAIL = PIÙ CORSI DIVERSI
==================================================

QUESTA È UNA REGOLA FONDAMENTALE

Voglio che uno stesso cliente/email possa avere più corsi diversi.
Esempio:
andreaaresini118@gmail.com
può avere:
- Corso Fade
- Corso Design
- Corso Color
MA
non deve poter avere due codici attivi per lo stesso identico videocorso, salvo eccezioni deliberate da admin.

NUOVA LOGICA DA IMPLEMENTARE

1. CONSENTITO
- stessa email
- più codici
- purché i codici siano associati a corsi diversi

2. NON CONSENTITO
- due codici attivi per la stessa email e lo stesso corso
- se admin prova a creare un secondo codice per la stessa email e stesso corso, mostra errore chiaro tipo:
  “Esiste già un codice attivo per questo cliente su questo corso”

3. DASHBOARD STUDENTE
- quando uno studente accede, devono comparire TUTTI i corsi sbloccati associati alla sua email
- non solo uno
- se ha 2 o 3 corsi diversi, devono vedersi tutti come card separate

==================================================
D. FLUSSO CORRETTO DI SBLOCCO CORSI
==================================================

RIDISEGNA E CORREGGI IL FLUSSO IN QUESTO MODO

1. ADMIN CREA CODICE
Quando admin genera un codice:
- seleziona il corso
- inserisce nome cliente
- inserisce email cliente
- salva
- il codice viene creato nel database
- stato = attivo
- quel codice è associato a uno specifico corso e una specifica email

2. CLIENTE INSERISCE CODICE
Quando il cliente entra nella sua dashboard o nella sezione “Attiva Codice”:
- inserisce il codice
- il sistema controlla che il codice esista
- controlla che sia attivo
- recupera il corso associato
- recupera l’email associata
- se il cliente è loggato con quella stessa email oppure la inserisce correttamente, il corso viene sbloccato

3. RISULTATO
Dopo attivazione corretta:
- il corso deve comparire davvero nella dashboard studente
- non deve uscire “Nessun corso sbloccato”
- il sistema deve leggere tutti i corsi attivi associati a quell’utente/email

4. SE IL CODICE È GIÀ ATTIVATO
- se il corso è già sbloccato per quell’utente, non andare in errore
- mostra messaggio tipo:
  “Questo corso è già attivo nel tuo account”
oppure
  “Corso già sbloccato”
- non duplicare il corso nella dashboard
