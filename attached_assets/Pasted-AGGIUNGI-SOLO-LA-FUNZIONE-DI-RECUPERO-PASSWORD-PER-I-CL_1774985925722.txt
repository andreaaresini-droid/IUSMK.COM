AGGIUNGI SOLO LA FUNZIONE DI RECUPERO PASSWORD PER I CLIENTI DEI CORSI, SENZA TOCCARE O ROMPERE NULLA DI CIÒ CHE GIÀ FUNZIONA.

OBIETTIVO
Voglio che un cliente che non ricorda più la password possa reimpostarla in modo semplice e sicuro.

FUNZIONI DA AGGIUNGERE

1) LINK NELLA PAGINA LOGIN
Nella pagina login cliente aggiungi sotto i campi email e password il link:

“Password dimenticata?”

Questo link deve portare alla pagina di recupero password.

2) PAGINA “RECUPERA PASSWORD”
Crea una pagina dedicata con stile IUSMK coerente con il resto del sito.

Testi:
Titolo:
“Recupera la password”

Sottotitolo:
“Inserisci la tua e-mail per ricevere il link di reimpostazione della password.”

Campo:
- E-mail

Pulsante:
“Invia link di recupero”

Sotto al form:
“Tornare al login”

3) LOGICA BACKEND RECUPERO
Quando il cliente inserisce la sua email:
- se l’email esiste, genera un token sicuro di reset password
- salva il token in modo sicuro (o salva il suo hash) con scadenza temporale
- invia al cliente un’email con link di reset password
- il link deve portare a una pagina del sito tipo /reset-password?token=...
- per sicurezza, il messaggio frontend deve essere neutro, ad esempio:
  “Se l’indirizzo e-mail è registrato, riceverai un link per reimpostare la password.”

NON rivelare se l’email esiste o no.

4) MODELLO DATI
Se necessario, aggiungi campi compatibili al modello utente o una tabella dedicata, ad esempio:
- passwordResetTokenHash
- passwordResetExpiresAt

Oppure una tabella PasswordResetToken con:
- id
- userId
- tokenHash
- expiresAt
- usedAt
- createdAt

Usa la soluzione più pulita in base alla struttura già esistente.
Non duplicare sistemi se c’è già qualcosa di riutilizzabile.

5) EMAIL DI RESET
Invia un’email reale usando il sistema email già presente nel progetto, se esiste.
Se esiste già un provider email configurato, RIUTILIZZALO senza rompere nulla.

Testo email:
Oggetto:
“Reimposta la tua password”

Corpo:
“Abbiamo ricevuto una richiesta per reimpostare la password del tuo account.
Clicca sul link qui sotto per scegliere una nuova password.
Se non hai richiesto tu questa operazione, puoi ignorare questa email.”

Aggiungi il pulsante o link completo di reset.

6) PAGINA “RESET PASSWORD”
Crea una pagina dove l’utente arriva dal link email.

La pagina deve contenere:
Titolo:
“Imposta una nuova password”

Campi:
- Nuova password
- Conferma nuova password

Pulsante:
“Salva nuova password”

7) LOGICA RESET
Quando l’utente invia il form:
- verifica che il token sia valido
- verifica che non sia scaduto
- verifica che non sia già stato usato
- aggiorna la password dell’utente con hash sicuro
- invalida subito il token dopo l’uso
- facoltativo ma consigliato: invalida eventuali sessioni precedenti
- reindirizza al login con messaggio di successo

Messaggio successo:
“La password è stata aggiornata correttamente. Ora puoi accedere.”

Messaggi errore chiari:
- link non valido
- link scaduto
- password non coincidenti
- password troppo debole

8) SICUREZZA
- password sempre hashata, mai in chiaro
- token di reset sicuro e non prevedibile
- token con scadenza, ad esempio 1 ora
- non mostrare mai se una mail esiste o no
- limita eventuali abusi con rate limit se possibile
- proteggi gli endpoint

9) INTERFACCIA
Mantieni lo stile grafico IUSMK:
- dark theme
- pulsanti rossi
- responsive mobile perfetto
- stessa coerenza grafica del login/registrazione

10) COSA NON DEVI TOCCARE
NON modificare o rompere:
- login già funzionante
- registrazione già funzionante
- Stripe
- corsi
- notifiche
- dashboard admin
- coupon
- qualsiasi altra funzione già stabile

11) RISULTATO FINALE
Il flusso corretto deve essere:
- cliente apre login
- clicca “Password dimenticata?”
- inserisce email
- riceve email con link reset
- apre il link
- inserisce nuova password
- salva
- torna al login
- accede con la nuova password

IMPORTANTE
Fai una modifica precisa e mirata.
Non aggiungere flussi finti.
Tutto deve essere reale e funzionante end-to-end.
Se manca la configurazione email, prepara il sistema in modo pulito e indica chiaramente quali environment variables servono.
