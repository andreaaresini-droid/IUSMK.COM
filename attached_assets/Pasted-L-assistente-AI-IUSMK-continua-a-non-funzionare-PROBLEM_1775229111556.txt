==================================================
1. DEBUG COMPLETO DEL FLUSSO
==================================================

Controlla in ordine tutti questi punti:

A) Il widget chat sta davvero chiamando l’endpoint corretto?
- verifica la route usata dal frontend
- verifica che il messaggio utente venga inviato correttamente
- verifica che sessionId e pageUrl arrivino davvero al backend

B) L’endpoint backend riceve davvero il messaggio?
- aggiungi log server temporanei
- logga il testo ricevuto
- logga eventuali errori

C) Il backend interroga davvero la Knowledge Base?
- verifica la query reale al database
- verifica che recuperi record con isPublished = true e isActive = true
- verifica che non ci siano filtri sbagliati che escludono i record

D) I record trovati vengono davvero usati per costruire il contesto?
- logga i record trovati
- logga il contesto finale passato al modello
- verifica che non sia vuoto o nullo

E) Il modello AI riceve davvero il contesto?
- logga il payload finale inviato al modello
- verifica che il system prompt e il contesto siano presenti
- verifica che non venga inviato solo il fallback

F) Il fallback parte per errore?
- controlla tutta la logica if/else
- verifica se usedFallback viene attivato anche quando ci sono risultati pertinenti
- correggi eventuali return anticipati o soglie errate

2. MODALITÀ TEST OBBLIGATORIA
==================================================

Voglio una modalità di test reale nell’admin AI dashboard.

Aggiungi una sezione o pannello chiamato:
“Test Assistente AI”

Questa funzione deve permettere all’admin di scrivere una domanda e vedere:
- domanda originale
- domanda normalizzata
- record KB trovati

- record selezionati
- contesto finale costruito
- risposta generata
- motivo del fallback, se scatta

Questo strumento serve a capire esattamente dove si rompe il flusso.

Non serve che sia bello, basta che funzioni bene.

==================================================
3. VERIFICA RECORD KB REALI
==================================================

Controlla che i record visibili nella dashboard:
- esistano davvero nel database
- abbiano davvero isPublished = true
- abbiano davvero isActive = true
- abbiano title/content/keywords valorizzati
- siano leggibili dalla funzione di retrieval

Se la dashboard mostra record ma il backend non li legge, correggi subito il problema.

==================================================
4. BYPASS TEMPORANEO AI PER TEST
==================================================

Per capire se il problema è il retrieval o il modello AI, implementa un test temporaneo:

Se il sistema trova record KB pertinenti, prima di inviare al modello AI fai una risposta diretta di test del tipo:
- prendi il contenuto del miglior record
- restituiscilo come risposta semplice

Se così funziona, allora il problema è nel passaggio al modello AI.
Se non funziona neanche così, allora il problema è nel retrieval/query DB.

Questo test serve solo per il debug, poi puoi mantenere il comportamento finale corretto.

- motivo preciso del fallback nei log
